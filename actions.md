# Текущая задача

## Цель
Покрыть серверную часть Django-приложения автоматическими тестами, добавить файл(ы) test.py/tests.py и подготовить краткую документацию по запуску и назначению тестов.

## 1. Что нужно протестировать

Необходимо покрыть базовую backend-логику приложения:

### Авторизация и доступ
- неавторизованный пользователь не должен получать доступ к защищенным страницам;
- авторизованный пользователь должен попадать на главную страницу;
- пользователь должен видеть данные только своей организации;
- пользователь не должен получить доступ к объектам другой организации.

### Роли пользователей
Проверить доступы для ролей:
- admin;
- dispatcher;
- engineer;
- chief_engineer.

Минимально проверить:
- admin может создавать/редактировать/удалять основные сущности;
- engineer не может удалять оборудование и локации;
- engineer может работать только со своими заявками;
- dispatcher может работать с заявками;
- chief_engineer может создавать и редактировать локации.

### Организации и пользователи
- создание OrganizationMembership;
- пользователь связан с организацией через OrganizationMembership;
- нельзя назначить Department из другой организации;
- переключение организации доступно только на организацию, где у пользователя есть active membership.

### Локации
- создание локации;
- редактирование локации;
- удаление локации;
- вложенность локаций через parent;
- фильтр по наличию оборудования;
- LocationModel хранит JSON техплана;
- удаление техплана удаляет LocationModel, но не удаляет Location.

### Оборудование
- создание оборудования;
- редактирование оборудования;
- удаление оборудования;
- массовое удаление оборудования;
- нельзя удалить оборудование другой организации;
- фильтрация и пагинация списка оборудования.

### Заявки
- создание заявки;
- при создании заявки создается запись History_Application с комментарием «Заявка создана»;
- редактирование заявки создает запись истории с комментарием «Были внесены изменения»;
- изменение статуса заявки создает запись истории;
- фильтр «Мои заявки» возвращает заявки текущего пользователя;
- фильтры по датам показывают ошибку «Неверный диапазон дат» при некорректном диапазоне;
- дедлайн меньше 2 дней корректно обрабатывается в контексте/шаблоне, если такая логика есть во view/helper.

### Справочники
- системный статус ApplicationStatus с code="completed" существует;
- системный статус нельзя удалить;
- ApplicationPriority.weight используется для расчета загрузки.

### Приглашения
- admin может создать приглашение;
- не-admin не может создать приглашение;
- приглашение создает OrganizationInvitation;
- принятие приглашения создает OrganizationMembership;
- нельзя повторно принять accepted/expired invitation.

### Email-приглашения
- при создании приглашения отправляется письмо;
- если письмо не отправилось, приглашение все равно создается;
- ссылка приглашения остается доступной для ручного копирования.

### Геосервис
- при сохранении Location с адресом вызывается геокодирование;
- если геокодирование не удалось, Location все равно сохраняется;
- latitude/longitude сохраняются при успешном геокодировании.

## 2. Формат тестов

Требования:
- использовать стандартный Django TestCase или pytest-django, в зависимости от того, что уже используется в проекте;
- если в проекте нет pytest, использовать стандартный django.test.TestCase;
- тесты можно разместить в tests.py приложения или в отдельной папке tests/;
- не ломать текущую структуру проекта;
- не добавлять тяжелые зависимости без необходимости;
- внешние API и email не вызывать реально, использовать mock.

## 3. Документация

Нужно добавить краткую документацию по тестам.

Формат:
- TESTING.md в корне проекта
или
- раздел в README.md, если отдельная документация не используется.

Документация должна содержать:
- что покрывают тесты;
- как запустить все тесты;
- как запустить тесты отдельного приложения;
- какие данные создаются внутри тестов;
- какие внешние сервисы мокируются;
- как интерпретировать результат.

## 4. Ограничения

- Не менять бизнес-логику без необходимости.
- Не менять models.py без необходимости.
- Не создавать миграции.
- Не делать реальные запросы к Яндекс Геокодеру.
- Не отправлять реальные email.
- Не трогать 3D-визуализацию.
- Не писать чрезмерно хрупкие тесты, завязанные на точную верстку.
- Тестировать поведение backend, права, редиректы, создание записей и работу с БД.
- Если какая-то функция отсутствует или называется иначе, адаптировать тесты к фактическому коду проекта.
