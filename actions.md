# Текущая задача

## Цель
Доработать расчет загрузки команды и пользователей:

- использовать weight из таблицы ApplicationPriority вместо фиксированного значения;
- корректно учитывать приоритет задач при расчете загрузки;
- обновить отображение на:
  - главной странице (загрузка команды);
  - странице пользователей (индивидуальная загрузка).

## 1. Загрузка команды (главная страница)

Сейчас:
- используется фиксированное значение (например, 10 за задачу).

Нужно:
- использовать поле weight из ApplicationPriority.

Логика:
- взять все активные заявки текущей организации;
- активные = заявки, где status.code != "completed";
- для каждой заявки:
  - взять priority.weight;
- team_load = сумма всех weight;

max_capacity:
- engineers_count = количество пользователей с ролью engineer;
- max_capacity = engineers_count * 100;

Отображение:
- progress bar от 0 до max_capacity;
- текст: «team_load / max_capacity»;
- цвет:
  - <60% — зеленый;
  - 60–99% — желтый;
  - >=100% — красный.

Важно:
- учитывать только заявки, назначенные на инженеров;
- учитывать только текущую организацию;
- если priority отсутствует или weight null → считать 0;
- если weight отсутствует в модели → НЕ добавлять поле автоматически.

## 2. Загрузка пользователя (страница пользователей)

Сейчас:
- используется фиксированное значение за заявку.

Нужно:
- использовать weight из ApplicationPriority.

Логика:
для каждого пользователя:
- взять все активные заявки, где executor = пользователь;
- активные = status.code != "completed";
- user_load = сумма priority.weight;

Отображение:
- progress bar Bootstrap;
- шкала 0–100;
- если больше 100:
  - бар = 100%;
  - текст показывает реальное значение (например, 130/100);
- цвет:
  - <60% — зеленый;
  - 60–99% — желтый;
  - >=100% — красный.

Если priority или weight отсутствует:
- использовать значение 0.

## Ограничения

- Не менять models.py без необходимости.
- Не создавать миграции.
- Не использовать fallback «10 за задачу».
- Не использовать User.type_user.
- Роль брать только через OrganizationMembership.
- Не учитывать заявки других организаций.
- Не ломать существующие фильтры, поиск и таблицы.
- Не трогать 3D-визуализацию.
