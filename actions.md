# Текущая задача

## Цель
Реализовать B2B-логику авторизации и управления пользователями организации:

1. Системный администратор создает Organization.
2. Системный администратор создает первого пользователя-админа организации.
3. Для него создается OrganizationMembership с role=admin.
4. Админ организации входит в систему.
5. Админ организации добавляет сотрудников через приглашения.

JWT не использовать. Использовать стандартную Django session-based authentication.

## 1. Авторизация

Требования:
- использовать стандартную Django-аутентификацию;
- настроить login/logout;
- после входа перенаправлять пользователя на главную страницу/статистику;
- основные страницы приложения должны быть доступны только авторизованным пользователям;
- если пользователь не авторизован, перенаправлять на страницу входа.

## 2. Создание организации и первого администратора

Требования:
- Organization создается системным администратором через Django Admin;
- User создается системным администратором через Django Admin;
- OrganizationMembership связывает User и Organization;
- первый пользователь организации должен иметь role=admin;
- OrganizationMembership.status должен быть active;
- роль организации не хранить в User.

## 3. Ограничение данных по организации

Требования:
- пользователь должен видеть только данные своей организации;
- фильтровать по organization:
  - Location;
  - LocationModel;
  - Equipment;
  - Application;
  - File;
  - History_Application;
  - History_Equipment;
  - Department;
  - OrganizationMembership;
  - OrganizationInvitation;
- если у пользователя нет активного OrganizationMembership, показывать понятную страницу/сообщение об отсутствии доступа;
- не показывать данные других организаций.

## 4. Приглашение сотрудников админом организации

Нужно добавить интерфейс приглашения сотрудников.

Требования:
- только пользователь с OrganizationMembership.role=admin может приглашать сотрудников;
- страница приглашения должна содержать форму:
  - email;
  - role;
  - department;
  - position;
  - date_reception;
- при отправке формы создается OrganizationInvitation;
- invitation.status = pending;
- invitation.organization = организация текущего админа;
- invitation.invited_by = request.user;
- invitation.token должен быть уникальным;
- expires_at должен заполняться, например на 7 дней вперед;
- после создания показать ссылку приглашения или страницу с подтверждением;
- отправку email можно не реализовывать на первом этапе, если в проекте не настроена почта.

## 5. Принятие приглашения

Нужно добавить страницу принятия приглашения по token.

Сценарии:
1. Если пользователь с email приглашения уже существует:
   - создать OrganizationMembership для этого пользователя;
   - role взять из приглашения;
   - organization взять из приглашения;
   - status = active;
   - department/position/date_reception перенести из приглашения, если эти поля есть;
   - invitation.status = accepted.

2. Если пользователя с таким email еще нет:
   - показать форму регистрации;
   - создать User;
   - создать OrganizationMembership;
   - invitation.status = accepted;
   - после регистрации авторизовать пользователя или перенаправить на login.

Требования:
- нельзя принять expired/cancelled/accepted приглашение повторно;
- нельзя принять приглашение после expires_at;
- нельзя создать дубликат OrganizationMembership для того же user + organization;
- после успешного принятия перенаправить пользователя на login или dashboard.

## 6. Страница пользователей организации

На странице пользователей:
- показывать только пользователей текущей организации;
- брать данные через OrganizationMembership;
- админ организации должен видеть кнопку «Пригласить сотрудника»;
- не показывать пользователей других организаций.

## 7. Права доступа

Минимальные правила:
- admin организации:
  - видит пользователей организации;
  - приглашает сотрудников;
  - управляет локациями, оборудованием, заявками.
- dispatcher:
  - работает с заявками.
- engineer:
  - видит назначенные или доступные заявки и оборудование.
- chief_engineer:
  - работает с оборудованием и заявками.
  
На первом этапе обязательно реализовать:
- доступ к приглашениям только для admin;
- фильтрацию всех данных по организации текущего пользователя.

## 8. Ограничения

- Не использовать JWT.
- Не добавлять DRF/JWT без необходимости.
- Не менять архитектуру на SPA.
- Не трогать 3D-визуализацию.
- Не хранить роль организации в User.
- Не показывать данные других организаций.
- Не создавать Organization через публичную регистрацию.
- Не удалять существующие templates без необходимости.
- Не ломать текущие страницы.
- Если нужны новые поля в OrganizationInvitation для department, position, date_reception — добавить их миграцией и объяснить.
- Если можно реализовать без изменения моделей, не менять models.py.
