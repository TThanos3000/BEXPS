# Тестирование BEXPS

## Цель

Автоматические тесты проверяют backend-логику Django-приложения: авторизацию, доступ по организациям, ролевую модель, CRUD-сценарии, историю заявок, локации, оборудование, приглашения и интеграционные точки, которые не должны обращаться к внешним сервисам во время тестов.

## Что покрыто

- Авторизация и защищенные страницы.
- Ограничение данных текущей `Organization`.
- Роли `admin`, `dispatcher`, `engineer`, `chief_engineer`.
- Создание и редактирование `Location`, включая parent-иерархию.
- Хранение JSON техплана в `LocationModel`.
- Мокирование геокодирования Яндекса при сохранении локации.
- Создание, редактирование, одиночное и массовое удаление `Equipment`.
- Пагинация и `per_page` на странице оборудования.
- Создание, редактирование и изменение статуса `Application`.
- Создание `History_Application`.
- Фильтры заявок, включая `mine=1` и ошибку диапазона дедлайна.
- Системный статус `completed`.
- Расчет нагрузки через `ApplicationPriority.weight`.
- Создание и принятие `OrganizationInvitation`.
- Обработка ошибок email-отправки без отката приглашения.
- Валидация, что `Department` в `OrganizationMembership` принадлежит той же организации.

## Как запустить

Из директории с `manage.py`:

```bash
python manage.py test
```

Только тесты приложения:

```bash
python manage.py test parmodels
```

Конкретный тестовый класс:

```bash
python manage.py test parmodels.tests.EquipmentTests
```

Перед тестами полезно проверить проект:

```bash
python manage.py check
```

## Тестовые данные

Тесты используют стандартный `django.test.TestCase` и создают данные внутри тестовой базы:

- две организации;
- пользователей с разными ролями;
- активные `OrganizationMembership`;
- департамент;
- локации;
- справочники статусов, типов и приоритетов;
- оборудование;
- заявки;
- приглашения.

Внешние зависимости вроде `factory_boy` не используются.

## Внешние сервисы

Реальные внешние вызовы в тестах не выполняются:

- Яндекс HTTP Геокодер мокируется через `patch("parmodels.views.geocode_yandex_address")`;
- отправка email-приглашений мокируется через `patch("parmodels.views.send_organization_invitation_email")`;
- Яндекс JavaScript API и Suggest API не вызываются в backend-тестах, потому что они работают в браузере.

## Если тесты падают

1. Проверь, что применены миграции и тестовая база может быть создана.
2. Запусти `python manage.py check`.
3. Запусти один конкретный класс тестов, чтобы сузить проблему.
4. Если падает тест с правами, проверь `parmodels/permissions.py`.
5. Если падает тест с организацией, проверь active `OrganizationMembership` и session key `current_organization_id`.
6. Если падает тест с внешним сервисом, убедись, что используется mock, а не реальный HTTP/email-вызов.
